## What these numbers do and do not show

- **Set A is in-sample.** These are ARVO's own crashing inputs for the cases verify.py was built and tested on. 6/6 shows the pipeline works end to end; it is not evidence about unseen real-world reports.
- **Set B is hand-made by us**, not real spam. These inputs are easy (they don't crash the parser at all). This backtest does not show that spam is stopped, and we make no such claim.
- **The control run is weaker than one commit per bug.** ARVO's fixed images are a later libucl version where the crash no longer happens, not each bug's exact fix commit. Five of the six fixed images are the same libucl commit `45997ad` (2022-01-06), and the sixth (42512369) is `8a0294f` (2025-06-04). The 42482847 and 42482848 vulnerable images are the same libucl commit (`875c251`). So `reproduced` means "this input triggers the expected ASan error in libucl code on the pinned vulnerable build, and the crash is gone in a later libucl". Set C shows this: real bug inputs give `reproduced` on other cases whose vulnerable build also has that bug.
- **Set C has 8 real-bug inputs that were forfeited.** In each, the chosen case's vulnerable build ran the input clean 3/3, so that build does not show the bug. A real bug submitted against the wrong pinned build loses its bond. We did not check why each build is clean (for example, whether the bug was added in a later commit). These are not counted as "wrongly forfeited", because the headline counts only bugs submitted against their own case.
- **A fixed image is not bug-free.** ARVO 42512369's input still gives a heap-buffer-overflow at `ucl_hash_search src/ucl_hash.c:460` on the `45997ad` fixed build (checked directly with `harness/arvo_case_check.py`'s runner, 2026-11-16).
- **Each verdict uses only one expected error type per case** (heap-buffer-overflow for all six). A real crash of another type (for example the SEGV rows in set C) is `inconclusive`: the bond is returned, but the bug is not credited as reproduced.
